# 整理后自测

每次整理完做这三项自检，**输出简短结论即可**（一两句/项），不要写冗长报告。

## a. 用户指令遵循（最硬的一项，不过则整个任务不合格）

把用户指令**逐条列出来对账**，每条回答三个问题：

1. **做了没有？** 用户列了 N 条就必须交付 N 条。漏做一条 = 不合格，不能用"其他条做得好"抵消。若某条因源材料缺失/歧义做不了，**必须在结尾显式说明是哪一条、为什么**，不能静默跳过。
2. **落在指定的笔记里了没有？** 用户点名了目标笔记（`@某笔记.md`）就只能写进那一份。觉得内容更适合别处 → **先说明再问**，不能自行改道。写错文件 = 指令不遵循，即使内容本身质量高也算失败。
3. **只做了要求的范围没有？** 用户说"补充 X 的基础操作"就只写 X 的基础操作，不附赠典型案例、实战链路、工程延伸。**没被要求的笔记一律不碰**——不要自造任务。

反面案例（真实发生过，务必规避）：用户要求「HTTP 状态码整理进 `计算机网络.md`」，实际写成了「pip 索引 403 排错整理进 `pip.md`」——目标笔记错、主题错、还顺手改了没被要求的第三份笔记。

## b. 阅读成本 / 快速可习得性（最重要）

是否以**最低阅读成本完整承载了知识点**？读者读完这段笔记，能不能不回看原文就掌握该知识点？
- 有没有冗余铺陈可删？
- 有没有丢掉理解必需的 nuance？
两者任一不达标即不合格。

自查动作：**写完把每一段重读一遍，问"删掉它读者会不会漏掉知识点"**——不会就删。典型该删的东西：同一结论换个说法重复一次、为示例再配一个"典型用法"、把两三条要点又汇总成一张表、"实战链路/工程语境"这类衔接段。**新增行数不是产出量的指标**；用户给一句话指令却收到 80 行，基本可以断定超标了。

## c. 风格一致性

是否贴合该笔记既有记录风格（编号小节、纲领开头、总链路、双链、表格完整、中文）？
融入的新内容读起来像不像原作者写的？

具体核对：**新增段落的密度**与相邻既有小节是否相当（既有小节一条 bullet 讲完的事，不要写成三段带小标题的展开）；**有没有默认追加"常见误解/易错点"**（不该追加，见 style.md 铁律 6）；**流程图有没有用文本画**（该用 json-canvas，见 style.md 铁律 12）。

## d. 结构清晰度

- 小知识点：**不动**既有结构，就近插入即可。
- 目录层级已明显混乱：才考虑整体重构，且**重构前先与用户沟通**（约束 e）。
- 检查同级章节是否混入了不同层级的内容。

## e. 格式正确性

验证本次调整、以及扫描中发现的既有内容，其 markdown / 公式格式是否正确渲染。重点排查：

- **表格单元格内的行内公式**：`$...$` 里出现裸 `|`（如 $\lvert x\rvert$、绝对值、范数、集合条件、行列式）会被 markdown 当成列分隔符，撑坏表格、并被 linter 重排出多余空列。**表格内一律用 `\lvert \rvert`、`\Vert \rVert`、`\mid` 代替裸 `|`**；`$$...$$` 独立公式块不受影响，可保留 `||`。
- **LaTeX 定界符配对**：`$`/`$$`、`\left`/`\right`、`{}`、`\begin`/`\end` 是否成对。
- **代码块围栏**：``` ``` `` 是否闭合、语言标注是否合理。
- **双链语法**：`[[笔记名#小节]]` 的 `#` 锚点是否指向真实存在的标题。
- 发现格式错误（含既有笔记里的）直接修正；若属知识性改动则走约束 c 先问。

## f. 目录重构专项验收（仅场景 E，见 `references/restructure.md`）

重构任务除上面 a–e 外，另做这五项验收：

- **知识完整性**（最硬指标）：重构前后知识总和**零变化**。只有空壳笔记/空目录被删，任何实质内容都只是换了位置，没丢、没改写走样。可用 `git diff --stat` / 迁移前后文件清单比对佐证。
- **结构清晰性**：新目录层级正交、无语义重叠、无同名嵌套、无空泛 catch-all；顶层类目一眼能分。
- **归纳恰当性**：每份笔记内容忠于其标题主题，错位内容需根据笔记主题适配度迁到正确笔记；合并的重复笔记保留了各自独有知识点；拆分的笔记单一主题。
- **双链有效**：全库扫描确认无断链；重命名的笔记、带路径的链接、索引笔记 `Sub-item` 均已同步更新。
- **图片引用有效**：迁移的笔记其图片已随迁到目标同级 `images/`，所有 `![[...]]`/`![](...)` 引用仍指向真实文件、未失效。

## 输出格式示例

知识融入场景：

```
自测：
- 指令遵循：✅ 3 条逐条对账，均落在指定笔记，未动其他文件
- 阅读成本：✅ 已压成 3 点 + 1 表，无回看原文必要
- 风格：✅ 沿用 0/1/2 编号 + 双链到 [[xxx]]，未追加常见误解段
- 结构：✅ 小知识点，就近插入 §3，未动整体结构
- 格式：✅ 表格内公式改用 \lvert\rvert，定界符/围栏/双链锚点均校验
（如有跳过的点/存疑处，在此一并说明）
```

指令是多条清单时，「指令遵循」那行改成逐条列：

```
指令遵循（8 条）：
1 HTTP 状态码 → 计算机网络.md ✅
2 device_map → 深度学习库.md ✅
...
7 量化格式 → 量化.md ⚠️ 源文件无相关内容，已说明，未动笔记
```

目录重构场景（场景 E）：

```
重构自测：
- 知识完整性：✅ 全程 mv 移动，零删除实质内容，仅删 2 个空壳目录
- 结构清晰性：✅ 顶层 9→7 域，消除三层同名嵌套与工程桶重叠
- 归纳恰当性：✅ ML 归一到算法工程；架构模式内容从设计模式笔记迁出
- 双链：✅ 全库扫描无断链，索引 MOC 已补 [[新目录]]
- 图片引用：✅ 随笔记迁移的图片已落到同级 images/，引用无失效
（对原方案的偏离/待用户定夺项，在此说明）
```
