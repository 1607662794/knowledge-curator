先读 `style.md`。A、B 使用同一抽取规范，B 额外读取用户指定文件。

## 抽取与核实

1. 优先处理用户点名的知识，将对话过程抽象为可复用机制，保留成立条件；不引入上一轮无关上下文。
2. 独立主题自洽成条，必要时配最小示例，密度贴合目标笔记；不为补充几个 API 扩写整篇教程。
3. 跳过授权范围外或仅在一次排错中成立的细节；用户明确要求记录案例时保留案例身份，不强行通用化。
4. 他模型回答 / 网帖须核实关键主张。尚未写入的新内容在核实后纠正、再融入，并说明实质偏差；改既有笔记含义时遵守 `SKILL.md` 的 c 项及本轮已有授权。
5. 公式定义、符号排版和适用条件按 `style.md`，不能因源材料口语化就继续使用模糊描述。
6. 去导航、站内搜索跳转和追踪参数，保留有证据价值的原始来源链接。网页清理可参考 `vendor/obsidian-skills/defuddle/SKILL.md`（相对 skill 根目录）。

## 源材料缺少指定内容

先搜索关键词与同义表达，再读取相邻段落核实；区分「没有匹配」与命令错误、编码错误或未读完整文件，不要求某个特定工具重复搜索。

确认缺失后，不以相邻主题顶替，也不擅自扫描其他私人聊天记录。只有用户授权了目录级范围时，才在该范围查找；使用不同源文件时明确说明。

源材料确无内容，或目标已覆盖，则在对账中说明「源缺失」或「已有覆盖」，不静默省略、不写无关内容凑数。

在目标笔记按事实粒度去重，只补差异。按 `testing.md` 的通用项验收，不依赖另一个已删除或未安装的聊天整理 skill。
