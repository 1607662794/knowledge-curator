# 源 C：论文整理

先读 `style.md`。论文笔记的科研表达须忠于论文；全文未读完、关键图表未核看，不开始归纳核心洞见。

## 读取与组织

1. 按 `toolchain.md` 用自带 PyMuPDF 脚本提取带页码全文，通读正文及相关附录。双栏、公式、表格的文本顺序可能错乱，需对照页面；没有文本层不代表页面为空。
2. 对关键图表渲染原页，检查坐标轴、图例、图注和关键数字。OCR 仅辅助识别，不能替代对图的核看，也不能替代原图资产。
3. 形成「痛点 → 作者洞见 → 方法 → 结果与边界」的全局认识，区分继承的前提、作者新增贡献和整理者解释。
4. 用紧凑总—分结构写入指定笔记；若只补局部知识则就近融入，不强加整篇模板。

## 总—分骨架

- **总览**：一句话或一段话解释论文解决了什么问题、核心做法及适用条件。
- **痛点 / 洞见 / 方法**：忠于原作。必要公式在使用处定义变量、形状和单位；保留论文记号，必要时说明与既有笔记的符号映射。
- **方法要点**：解释机制和关键公式；论文关键原图优先用于呈现该机制。复杂关系需自绘时按 `diagram.md`，没有图示收益就不加图。
- **效果**：优先选最有代表性的 1–3 个数字或结论，保留数据集、模型 / 任务、位宽 / 配置、硬件和基线等影响理解的实验条件。提升是相对还是绝对、测的是吞吐还是时延，要明确。
- **实现与边界**：仅保留论文中可复用的实现细节、超参数、数值稳定性和失效情形；不把经验观察扩张成普遍保证。

## 论文原图：必须实际保留

**每份论文知识提取笔记至少嵌入一张该论文原图；仅该论文全文确实一张图都没有时例外。** 多论文合并笔记按每篇有图论文分别满足；既有笔记已包含合格原图时复用，不重复堆图。只挑最能支撑本次核心机制或结论的图，不要求收录全部图片。

- **原图定义**：从该论文 PDF 直接导出的完整图像对象，或对原页中图区域的忠实渲染裁剪。后者可同时保留矢量线条、文字和位图，属于论文原图。重绘图、生成式图片、OCR 文本、表格截图不能充当这一要求中的原图。
- **选图与裁剪**：优先机制 / 架构图或关键结果图。保留必要的全部子图、坐标轴、单位、图例和子图编号。图注可一并裁入；若在图外，用笔记文字准确说明，注明原图号及来源。
- **导出与核看**：按 `toolchain.md` 先渲染整页确定边界，再以 300 DPI 为起点裁剪。打开导出图片检查，字号不足时调整分辨率或嵌入尺寸，不能用「脚本成功」代替视觉验收。
- **落盘与来源**：存到笔记同级 `images/<论文标识>-fig<图号>.png`，保留同名 JSON 来源记录（PDF 标识 / SHA-256、1-based 页码、裁剪框、分辨率、工具版本和图片哈希）。来源记录用于复核，正文不必复制全部技术字段。
- **正文嵌入**：使用能解析的图片引用，在旁边标记论文、原图号、PDF 页码及必要的一句解释。例如：

```markdown
![[paper-id-fig1.png]]

图 1（原论文 Fig. 1，PDF 第 2 页，来源：论文题名 / DOI 或本地 PDF）。
该图比较……，用于说明……。
```

- **无图例外**：检索图号和图注并核看全文页面（含附录）；纯矢量图可能使 `get_images()` 返回零，不能据此宣称无图。验收注明检查过的版本与页数，以及「全文无图」的依据。
- **暂时无法满足**：只有摘要、PDF 未取得、提取失败或图像不可辨认，均不等同于论文无图。明确报告原图项未通过及阻碍，不能将任务标为完整验收通过。

论文原图保留原始符号和配色；科研风格通过准确的来源、解释、记号映射和清晰度体现，不应改画原图来统一视觉风格。完工后执行 `testing.md` 的通用项及论文专项。
