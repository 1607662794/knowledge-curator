# 自绘科研图

知识提取、重构中的配图与独立绘图均先执行 `style.md`。论文原图按 `paper.md` 保留原貌；本文件规定自绘图，不能用自绘图替代论文原图硬门槛。

## 何时出图

| 情形 | 做法 |
| --- | --- |
| 用户明确要求绘图 | 交付图及必要说明 |
| 分支、汇聚、并行、多个组件关系难以用短文说明 | 用 draw.io 图建立关系 |
| 长笔记需要可视化全局骨架 | 设置总链路并出图 |
| 三四步以内的简单线性关系 | 一句话或 `A → B → C` 即可，不强制出图 |
| 纯对照关系 | 用表格 |
| 小知识点补充或纯目录移动 | 不为套模板额外出图 |

「有总览」不等于「必须有总链路章节」。图应减少理解成本，不给每份笔记强制添图。

## 文件与引用

本机 Obsidian `drawio` 插件 v3.1.1（somesanity 版）的现有工作流使用 `.drawio.svg`；换机器或升级时重新检查支持情况。

每张自绘图在笔记同级 `images/` 保存：

- `<笔记名> <主题>.drawio`：可编辑 XML 源。
- `<笔记名> <主题>.drawio.svg`：带嵌入 mxfile 的 SVG，用于预览和编辑。

笔记嵌入 `![[<笔记名> <主题>.drawio.svg]]`；名字可能重复时用可消歧路径。独立绘图没有宿主笔记时，使用用户指定输出位置，或约定目录的 `images/` 并说明。

## 生成与可编辑性

1. 探测可用 draw.io 技能、CLI / 桌面导出能力及 Obsidian 插件；技能路径按实际安装位置解析，不引用某次任务的临时脚本。
2. 有可靠导出工具时，先生成 `.drawio`，再导出包含图数据的 SVG。仅有静态 SVG 不自动满足可编辑要求。
3. 没有导出工具时，可以用脚本从**同一份节点、边、布局数据**生成 XML 与 SVG；不能各自手改导致两份内容漂移。XML 骨架、连接端口和样式细节可参考当前可用的 drawio 技能；没有该技能不等于可跳过验证。
4. SVG 内嵌原始 XML 方案使用 `content` 属性保存去掉声明行的 mxfile，正确转义属性值；若导出工具采用编码 / 压缩形式，按其格式解码验证，不强行当作原始 XML。
5. 用 XML 解析器检查源文件和 SVG；提取 / 解码嵌入模型后检查其节点、标签、边与源文件一致。可编辑性最终以编辑器实际打开为准，未打开时说明未验证。

没有 Graphviz 也可以手动布局；没有 draw.io CLI 不等于必须放弃原图导出或自行声称工具不支持。工具探测与降级结果如实报告。

## 科研排版

- 流程顺序明确，主方向统一；节点对齐、间距合理、留白充足。图的方向按内容决定，不强制所有图竖排。
- 箭头标注必要的数据 / 动作 / 依赖，避免意义不明的连线。前提、代价和限制可用旁注，但不强制每一步都附一个框。
- 默认少量低饱和颜色；同一颜色 / 线型对应稳定语义。颜色承担区分职责时有标签或图例，黑白显示仍能理解；不套固定「红=问题、黄=外推」模板。
- 符号遵循 `style.md`：标量斜体、向量与矩阵粗斜体，算子、单位和文字标签正体；论文记号差异有说明。图内或图注定义关键符号，不能依赖读者猜测。
- 简单公式可用 HTML / SVG 的上下标与字体样式；复杂公式用已验证的数学渲染器生成可显示内容。不能仅设置 `math=1` 就假定 Obsidian 内嵌 SVG 会自动运行 MathJax。
- 科研图以最终渲染为准：检查变量、粗斜体、上下标、中文、换行和箭头；不让原始 LaTeX 代码暴露在成图中。

## 验证

有可用的 drawio `validate.py` 时，先读其帮助，再用对应参数进行结构和布局检查；记录实际输出，不能沿用旧版本对 score 越高 / 越低的假设。修复错误，对警告逐项分析；合理的结构或连线交叉不为凑分数而扭曲语义。

无论是否有自动工具，都要核看渲染图：无裁切、无文字遮挡、无错误连线、公式正确，正常嵌入尺寸清晰。脚本评分或 XML 解析通过不能替代这一检查。最终按 `testing.md` 的通用项与 h 项验收。
