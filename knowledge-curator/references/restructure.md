# 场景 E：目录重构

当 vault 笔记积累到一定程度、目录结构变乱时，对 vault **自身已有内容**做结构性整理。这不是往里加新知识，而是**重组既有知识**。

## 铁律：只搬运重组，绝不增删知识

重构前后**知识总和必须完全守恒**——只改变"知识放在哪、怎么组织"，不改变"有哪些知识"。任何看似要删的内容，实为"迁移到更合适的位置"。真正的删除只针对**空笔记、空目录**（内容已迁走后的空壳）。

## 铁律：权限大，必须先沟通、拿方案确认再动手

重构涉及跨目录移动、删除、重命名，影响面远大于普通融入（约束 e 的强化版）。流程**强制**：

1. **先摸清现状**：`find` 列出目标范围内所有目录与文件（`.md`/`.canvas`/`.xmind`/`images`）。
2. **诊断问题**：找出重复笔记、错位内容、语义重叠目录、同名嵌套、catch-all 空泛筐等。
3. **出完整迁移清单**：逐条列"源 → 目标 + 操作类型 + 理由"，**先给用户过目**。
4. **等用户确认/调整**后再动手。用户明确"你自己决定"时可径直执行，但仍需在动手前展示清单、动手后报告。
5. 若执行中发现清单与实际文件不符（如某目录内容与预期不同），**停下重新确认**，别硬套方案。

## 重构可包含的动作

| 动作 | 说明 |
| --- | --- |
| 移动目录 | 整个子树挪到新父目录下 |
| 新建目录 | 为归纳出的新类目建目录 |
| 移动笔记 | 单个笔记挪到更合适的目录 |
| 新建笔记 | 为拆分/合并出的主题建新笔记 |
| 迁移笔记内容 | 把某笔记中**不属于其主题**的段落，移到更恰当的笔记 |
| 合并重复笔记 | 多个讲同一主题的笔记并成一个（保留全部独有知识点） |
| 拆分笔记 | 一个笔记塞了多个不相关主题时，拆成多个 |
| 归纳关联笔记 | 把分散但相关的笔记收进同一目录/加索引双链 |
| 删除空笔记 | 内容已迁走的空壳 |
| 删除空目录 | 文件已迁走的空目录 |
| 重命名目录/笔记 | 消歧、去连字符、统一命名风格 |

## 归纳恰当性：内容忠于笔记主题

重构的核心判断是**"这段知识属于哪个主题"**：

- 每份笔记的内容都应**忠于其标题主题**。发现某笔记里混入了不属于它的内容（如"设计模式"笔记里混了"架构模式"），迁到正确的笔记。
- 合并重复笔记时，**逐条比对知识点**，确保被合并方的独有内容全部保留，不因"看起来重复"就丢弃差异。
- 拆分时，按主题聚类，每个新笔记单一主题、同级不混层。

## 操作顺序建议（先易后难，分批验证）

1. **零歧义的纯修复先做**：拍平同名嵌套目录、明显的重命名。
2. **移动/合并目录**：按确认的清单批量 `mv`，每批做完 `find` 验证。
3. **文件级内容迁移**：涉及"某笔记的某段落搬到另一笔记"时，逐个 Read→Edit，最谨慎。
4. **收尾**：删空壳、更新索引笔记、修双链与图片引用。

## 双链维护（Obsidian 特性，重构最大的坑）

- **Obsidian 短链 `[[笔记名]]` 只认文件名、不认路径**：所以**纯移动目录、不改文件名时，短链通常不会断**。这是重构可以放心移动目录的前提。
- **会断的情况**：① 带路径的链接 `[[目录/子目录/笔记]]`；② frontmatter `Sub-item` 里写了全路径；③ 重命名了笔记文件本身。
- **重构后必做**：全库扫描 `grep -rn "\[\[.*<涉及的旧目录名/旧笔记名>.*\]\]" --include=*.md`，逐条核验受影响的链接，重命名笔记时同步改所有引用它的地方。
- **索引笔记**：含 `Sub-item` frontmatter 的目录索引（MOC）笔记要同步更新，反映新结构、补上新目录的双链。

## 图片位置与引用（重构必查）

- **规范**：某份笔记引用的图片，应放在**该笔记同级目录下的 `images/` 目录**内。
- **移动笔记时**：连同它引用的图片一起迁移到目标位置的 `images/`，并确认 `![[图片名]]` / `![](images/图片名)` 引用不失效。
- **合并/拆分笔记时**：图片跟着引用它的内容走，落到新宿主笔记同级的 `images/`。
- **重构后必做**：核查所有 `![[...]]` 与 `![](...)` 引用，确认路径仍指向真实存在的图片文件（Obsidian embed 短链同样认文件名，但 `![](相对路径)` 形式会因目录变动而失效，需改）。

## 完成后

按 `references/testing.md` 的重构专项验收准则自检（知识完整性、结构清晰性、归纳恰当性、双链有效、图片引用有效），输出简短结论。若本轮用户给了重构口味上的反馈，按 `references/taste-memory.md` 沉淀。
