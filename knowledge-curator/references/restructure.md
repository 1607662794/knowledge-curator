# 场景 E：笔记重构

重组 vault 既有知识，先读 `style.md`。知识守恒与科研表达同时成立：组织可以变，独有事实、条件、公式、来源和图不能丢。

## 范围与授权

1. 用 `rg --files` 或本机文件工具枚举授权范围内的笔记、图、Canvas 等资产，读取必要内容，定位重复与错位。
2. 在编辑前说明「源 → 目标 + 操作 + 理由」，以及涉及的入链、索引和图片处理。
3. 大范围重构按 `SKILL.md` 的 e 项取得方案授权；用户已批准具体方案或明确授权自行决定时继续执行，不再反复确认。
4. 执行前检查版本控制 / 备份与未提交改动；不假定文件已经备份，不覆盖用户未保存的并行修改。
5. 实际情况超出已授权主题或有实质内容歧义时暂停相关动作并澄清；清单内的常规路径调整无需反复索取同意。

## 知识守恒与科研规范

- 可移动、重命名、合并、拆分、调整章节、创建必要目录与索引；只删除内容已完整迁出且引用处理完的空壳笔记 / 空目录。
- 合并前按知识点比对：完全重复表述可合为一处，全部独有信息和上下文差异必须保留。「知识守恒」不要求逐字重复，更不意味着保留两份相同段落。
- 章节调整后，变量定义仍在首次使用前或邻近处；来源、图注、实验条件跟随对应结论，不能把公式与前提拆到无关联处。
- 允许语义不变的排版、记号映射与等价改写；补造新知识、删除结论或修正知识性错误按 `SKILL.md` 的 c 项处理。
- 纯目录移动不触发全文重写。发现原笔记不符合科研规范时，只在授权范围内规范化；无法无歧义处理的定义或结论问题单列说明。
- 纯重构保留已有论文原图；不强制重构任务另行下载论文补图。若本轮还要求论文知识提取，则执行 `paper.md` 的原图要求。

## 执行与内容映射

按主题判断每段内容的归属；单份笔记服务明确主题，同级不混层。先记录源到目标的映射，再分批完成移动、合并 / 拆分、索引更新和引用修复。

纯移动可比较文件哈希；内容迁移需逐条核对独有知识的目标位置。文件数、行数或 `git diff --stat` 只能辅助检查规模，不能证明没有丢知识。

## 双链与资产

- `[[笔记名]]` 可按文件名解析，但遇同名笔记存在歧义；移动后需确认实际解析目标。不能把「纯移动通常有效」当成无需检查。
- 带路径链接、Markdown 相对链接、frontmatter `Sub-item`、标题锚点与块引用都可能受移动、重命名或章节调整影响。
- 在全库扫描本次改动的入链；按已授权方案只修复受影响的引用，不顺手治理所有历史断链。需要修改方案外笔记的实质内容时另行澄清。
- 图片放新宿主笔记同级 `images/`，论文原图的 JSON 来源记录、自绘图的 `.drawio` / `.drawio.svg` 成对处理。
- 共享图片先找全部引用方：按需要复制到各宿主目录，或在授权方案中保留可解析的共享位置；不能直接搬走导致其他笔记断图。
- 同名不同内容的资产不能覆盖；重命名并更新引用。只清理确认不再被引用的旧资产，不仅凭某一份笔记已改完判断。
- 移动或删除前核对解析后的绝对路径，确保在授权目标内；文件操作使用当前平台原生工具，避免跨 shell 拼接删除命令。

完成后按 `testing.md` 的 a–f 自检，说明实际变更、保留依据与未解决项。
